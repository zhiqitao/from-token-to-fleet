The chapter sizes fleets at the 95th-percentile turn scenario (T=3) per its own rule (“size for the 
95th-percentile token scenario”), so the agentic columns use T=3 — which is also what the §17.8 mini-case 
computes (~152 hosts at 100 rps). C is the KV-residency ceiling (derived): 17.5 concurrent full-context 
requests on FP16 at T=0 (conservative integer floor 17), 13.8 at T=3 (12,095 tokens × 2.62 MB ≈ 31.7 
GB/request over 436 GB; floor 13), and 27.5 on FP8 at T=3 (12,095 × 1.31 MB ≈ 15.85 GB/request; floor 27 
— the mini-case’s “≈74 working hosts at FP8” at 100 rps). Each C is floored to a whole-sequence slot count 
(17, 13, 27) before the 0.7 utilization factor is applied in the host columns (integer-slot convention); the 
N−1 failover row adds one spare host. The 70% utilization target and the λ, W values are ILLUSTRATIVE 
scenario inputs to be validated by a deployment benchmark (Chapter 14) before committing hardware. 
N is a KV-residency lower bound — the true answer is the max of this KV bound and the measured 
throughput bound. Planning-bound caveat: the per-host figures that feed this table — ~2.0 req/s/host 
and ~19,800 prefill tok/s/host (Ch 8, idealized) — are upper-order planning bounds derived from the 
KV-residency/service-time model and the idealized prefill roofline, not implied deployed rates. No 
p95/p99 performance guarantee has been shown for any host count in these columns; the achieved 
p95/p99 tail latency and goodput must be measured on the target deployment (Chapter 14) before any 
host count is treated as validated.
