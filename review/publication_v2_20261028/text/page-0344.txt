• decode — the autoregressive pass that generates the output one token at a time from the built 
state. Often memory-bandwidth-bound at low batch (small arithmetic intensity per emitted 
token), but not invariably so; large-batch and bandwidth-friendly regimes can move it. Refer to 
the operating-point discussion in Ch 8, §8.2 for the conditional, not unconditional, classification.
• goodput — useful throughput: throughput that meets the latency/quality bar, discounting 
failures.
• P/D disaggregation — running prefill (P) and decode (D) on separate pools/services.
• continuous batching — scheduling new requests into a running decode batch so the GPU is 
kept busy token-by-token rather than waiting for an entire batch to finish; raises throughput 
at some latency cost.
• chunked prefill — splitting a long prompt’s prefill into sub-blocks interleaved with decode 
work, so a long prompt does not monopolize the GPU and stall latency-sensitive decode.
• FlashAttention — an I/O-aware attention kernel that tiles/fuses the Q·K·V computation 
through fast on-chip storage, reducing HBM traffic while preserving the same attention 
mathematics.
• PagedAttention — a memory-management strategy for the KV cache that allocates key/value 
blocks in non-contiguous pages, reducing fragmentation and enabling near-full memory 
utilization.
• speculative decoding — a draft model proposes a candidate sequence that the target model 
verifies in parallel, accepting matching tokens to raise effective throughput at the cost of draft 
+ verification compute.
• MFU — model FLOPs utilization: achieved FLOPs as a fraction of hardware peak.
• RPS / QPS — requests per second / queries per second: a rate of incoming work, the primary 
input to a capacity model.
• concurrency — the number of requests in flight (being served) at the same time; distinct from 
concurrent users, which is a population measure, and related to the arrival rate by Little’s law 
(in-flight ≈λW) (Ch 17, 20).
Memory and attention
• KV cache — the keys/values of past tokens retained so attention need not recompute.
• KV quantization — reducing the bytes per K/V element (e.g. FP16 → FP8), not the number of 
K/V entries; the canonical raw byte-halving is 2.62 → 1.31 MB/token (exactly 50%), a raw-array 
figure that is not a vendor-measured engine footprint, and the vLLM FP8-KV blog’s 54% is a 
decode-ITL latency slope, not a memory ratio (Ch 2, 6, 7; S6).
