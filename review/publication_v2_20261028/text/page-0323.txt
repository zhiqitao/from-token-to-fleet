Capstone Execution. The architect instruments all three scenario quantities, observes the 
derived quantities in real time, and validates each HYPOTHESIS against measured traffic. The result: 
one 8×H100 serving host + a 35% semantic response cache + circuit breaker yields an illustrative p99 
TTFT ≈ 250 ms at ~48% lower generation cost versus the ~450 ms uncached single-node baseline 
(one 8×H100 host, already tensor-parallel across its 8 GPUs) — the single capstone configuration, 
derived step by step in §26.8 and recorded as Table 26-2 (scenario outcome, not a measured benchmark). 
The Pattern-Measurement-Feedback Loop confirms the hypothesis that caching + load shedding is 
net positive, and the architect documents the configuration as a reusable pattern instance.
Alternatives considered. Two obvious alternatives were rejected against the canonical con­
straints. Prefix caching alone reuses prefill compute behind an exact-prefix match but still generates 
the answer, so the 35% repeat population keeps paying full decode — it does not skip the generation 
the semantic cache skips. A second serving host with load balancing is rejected because the bottleneck 
is concurrency/KV residency, not per-host throughput: Pattern A’s own hypothesis puts the gain at 
< 5% per request, so a second host doubles the fleet for single-digit improvement. Deeper continuous 
batching on the single host instead of sharding raises throughput by lengthening the in-flight queue, 
adding queueing delay exactly where the p99 TTFT SLO binds (Ch 8’s decode economics; Ch 15’s 
congestion check). Sharding + semantic cache + circuit breaker wins because it attacks the baseline’s 
own terms — model compute (sharding), the retrieval step (cache hits), and tail queueing (circuit 
breaker) — that each rejected option leaves in place.
