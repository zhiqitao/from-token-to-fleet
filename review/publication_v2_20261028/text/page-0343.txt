Glossary of Acronyms and Common Terms
Model fundamentals
• tokenization / tokenizer — splitting text into the model’s vocabulary of integer IDs; a token 
is whatever the model’s tokenizer decided to carve the text into (learned BPE-style merges), 
so token counts are tokenizer-dependent — run the model’s own tokenizer on representative 
traffic rather than a characters-per-token rule of thumb (Ch 1).
• embedding — the lookup that maps each discrete token ID to the dense vector the model 
actually operates on; the pipeline is text → tokenizer → IDs → embedding → attention → KV 
cache (Ch 1).
• attention — the mechanism that compares each token’s query (Q) against every prior key (K) 
and blends the values (V) by those scores; a processed token’s K/V never change, which is why 
they are cached (the KV cache) rather than recomputed each step (Ch 2).
• logits — the model’s raw, unnormalized per-vocabulary scores at a generation step; the sampler 
turns them into the next token (Ch 2).
Inference and serving
• TTFT — time to first token: latency from request to the first output token (prefill-dominated).
• TPOT — time per output token: steady-state decode latency per token.
• ITL — inter-token latency: the decode phase’s per-token lag; the book treats TPOT (steady-
state) and ITL (per-token, incl. any measured inter-token gap) as the same canonical per-token 
metric and writes them “TPOT/ITL.” Where a measurement distinguishes them, treat ITL as 
the per-token value that includes any queueing/scheduling gap between emitted tokens, i.e. a 
tail-sensitive complement to bounded TPOT.
• tail latency — latency at the high percentiles of the distribution (p95/p99), set by the slow­
est requests rather than the typical one; the SLOs in this book are written against the tail 
(TTFT/TPOT p95/p99), so a median that meets its budget says nothing about the tail (Ch 20).
