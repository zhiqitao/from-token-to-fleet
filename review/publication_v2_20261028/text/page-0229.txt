17.4.2. Simultaneous feasibility check (prefill + decode coexistence)
The ~2.0 req/s/host ceiling assumes prefill and decode run on the same host at the same time. We 
check the prefill leg against the hardware.
• (a) Prefill demand at 2 req/s. 2.0 req/s × 9,200 input tokens = 18,400 input tokens/s per 
host (2.0 × 9,200; the prefill leg of the ~2.0 req/s decomposition in the reconciliation box above).
• (b) Idealized prefill ceiling. 8 × 0.989 PF/s × 35% / (2 × 70e9) ≈ 19,780 tokens/s (Chapter 8, 
35% MFU, prefill-only).
• (c) The ratio. 18,400 ÷ 19,780 ≈ 93%. Prefill must run at ~93% of the idealized prefill ceiling.
This result is [ANALYTICAL]. It is a prefill-load check, not a measured rate. The ~93% leaves 
very little headroom. The host must also run decode. Prefill and decode coexist on the same hardware. 
Batch scheduling, prefill/decode interleaving, and interference consume the same compute. The 
idealized ceiling assumes no decode interference. The achieved MFU is below the 35% ideal. The real 
headroom is smaller than ~93%.
Therefore the ~2.0 req/s/host figure is an analytical upper bound. It is NOT a claim that a 
host serves 2 req/s at SLO.
Before treating 2 req/s/host as deployable, measure the p95 TTFT, p95 TPOT, and SLO-goodput 
on a representative host. Bring a measured p95 TTFT/TPOT and SLO-goodput (Chapter 14) before 
treating 2 req/s/host as a deployable service rate. Until then, the sizing in this chapter is a planning 
bound.
