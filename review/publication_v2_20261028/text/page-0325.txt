26.8. End-of-Chapter Mini-Case: The Capstone: Composing the Patterns
Scenario. A growing AI startup moves from a single-node prototype to a fleet serving ~3,000 users. 
The initial deployment is a 70B FP16 model on a single 8×H100 node (the canonical host). Note the 
per‑host ceiling: with the canonical ~8.6 s service time and C ≈ 17.5 KV‑resident requests, one host 
serves ~2.0 req/s (Ch 17/20) — so the figures below are expressed as TTFT p99 on that host (the 
sub‑second latencies are time‑to‑first‑token, not end‑to‑end), and the rps is the ~2 req/s the host can 
actually sustain, not a multiple of it.
Step 1 — Instrument. FACTs collected: request rate ~2 rps (within the ~2.0 req/s per‑host ana­
lytical planning ceiling), GPU utilization 45%, per-query latency breakdown for a baseline (uncached) 
request: model compute 320 ms, I/O 80 ms, retrieval 50 ms — the RAG retrieval step every request 
pays. The baseline has no cache installed, so there is no cache-miss path in it; the 50 ms is plain 
retrieval, and Pattern B’s hit path later covers the same ground (retrieval + lookup) without the 
engine. These components sum to a ~450 ms baseline TTFT, which the capstone uses directly as 
the baseline p99 scenario value (a scenario input, not a derived quantile of a distributed sample; a 
real baseline p99 must come from a measured latency distribution). Note the component values are 
representative worst-case estimates for a baseline request, and the ~450 ms is therefore the baseline 
TTFT figure used throughout; the per-query values are not a p99 of a separate measured distribution. 
Because the 50 ms retrieval term is part of the baseline, the headline −44% is measured against the 
full 450 ms path; excluding that term entirely (a 400 ms baseline) would report (400 − 250) / 400 = 
37.5% instead.
Step 2 — Pattern Apply. The architect applies Pattern A (inference sharding across an 8×H100 
node) and Pattern B (semantic response cache with 5-min TTL). [canonical scenario][DERIVED] — 
sharding distributes the model across the node so decode lands in the bandwidth-bound regime; 
cache hit ratio 35% reduces the number of requests that reach the model engine from ~2.0 rps to ~1.3 
rps (2.0 × (1 − 0.35) = 1.3). The TTFT and cost figures below are scenario estimates for this illustrative 
configuration, not measured values. A weighted average of component latency values is a mean, 
not a quantile, so the capstone separates the two. Under the transparent two-point model — 
a cache hit returns at a fixed ~50 ms (retrieval + cache lookup, no LLM prefill), and a cache miss 
is served by the engine at ~250 ms (a scenario value after the 35% lower arrival rate has settled 
the prefill queue) — the pooled latency has the CDF F(50) = 0.35, F(250) = 1.0. Its mean is 
0.35 × 50 + 0.65 × 250 = 180 ms, but its p99 is 250 ms (because the 0.99 quantile falls in the miss 
population: 0.35 < 0.99 ≤1.0). So mean TTFT ≈ 180 ms. p99 TTFT ≈ 250 ms (the miss value, not 
a blend). −44% TTFT against the ~450 ms uncached p99 baseline — (450 −250)/450 ≈44%. −48%
