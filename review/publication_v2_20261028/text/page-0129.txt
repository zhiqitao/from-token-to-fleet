All figures trace to the canonical scenario (Ch 4, Table 4-2) and validated sources; none are measure­
ment claims. This is the prefill compute demand. An 8×H100 node can sustain some fraction of this 
at MFU (model FLOPs utilization), which we estimate next.
8.3.3. Sustained vs. peak: H100 MFU
NVIDIA H100 SXM5 lists ~1,979 TFLOPS FP16 Tensor Core peak “with sparsity” and ~989 TFLOPS 
FP16 peak without sparsity [1P: NVIDIA H100 datasheet]. In practice, sustained model FLOPs 
utilization (MFU) for a well-tuned transformer workload typically runs at 30–40% of peak on H100 
[2°: industry benchmark reports, derived from real kernel profiles]. At 35% MFU:
sustained = peak × MFU = 989 TFLOPS × 0.35 ≈346 TFLOPS
[1P][2°][DERIVED: vendor peak (1P) × typical MFU (2°) — the MFU range is a secondary, empirical 
figure, so the sustained value inherits the provenance of its weakest input, the 2° MFU, while the 
peak is first-party]
Scope matters here. The 346 TFLOPS figure is the sustained rate of a single H100, and the 2,471 
tokens/s derived from it is therefore a per-GPU number. The canonical host is an 8×H100 node, so 
we must not multiply demand by a per-GPU rate as if it were per-node. Track the scope explicitly as 
we scale.
