The architect proposes the single 8×H100 host (TP within the node, so intra-node NVLink carries 
the per-step activation all-reduce) for the core serving fleet, with a fallback to a 32‑node RoCE cluster 
only if KV concurrency or memory capacity exceeds one host (Chapter 17). The communication 
arithmetic made the trade-off explicit: TP activation exchanges are tens of MB and free within NVLink; 
cross-node weight/KV shuttling is 35× more expensive and avoided unless the fleet genuinely spans 
hosts. The design is now grounded in bandwidth and the specific parallelism scheme, not in vague 
notions of “scale.”
Scope note. This conclusion decides the communication scheme, not the fleet size, and it is stated 
for the canonical workload (~10/40 rps, Ch 4, Table 4-2) that the rest of the book’s arithmetic uses — 
not for the 10,000-concurrent-user figure in the setup. At that stated scale the fallback condition in 
the sentence above is met on arrival: one 8×H100 host holds only C ≈ 17.5 concurrent full-context 
requests (Ch 17), so 10,000 concurrent users exceed a single host’s capacity by ~570× (10,000 ÷ 17.5 ≈ 
570 hosts regardless of fabric) — a Chapter 17 capacity question, not a fabric question. The single-
host-versus-RoCE choice above is what governs the canonical scale, where per-step TP activation 
exchanges stay tens of MB inside NVLink.
