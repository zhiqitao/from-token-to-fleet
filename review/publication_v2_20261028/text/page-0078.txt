A note on the canonical example’s limits. The input-heavy enterprise-RAG workload above 
is one shape, not the whole space. The same six-dimension framework characterizes any inference 
workload; what changes is which dimension dominates and which decision reverses. The compact 
ledger below is a transfer aid, not five parallel case studies — for each shape it names the changed 
dominant constraint and the single decision that would flip relative to the canonical RAG case.

The canonical RAG case is input-heavy (9.2K in / 300 out), so prefill compute and KV residency 
dominate. Each row above is a workload where a different dimension takes over — and the architecture 
that is right for the canonical case is not automatically right for it. This is why the book keeps the 
six dimensions separate rather than collapsing them into one “throughput” number.
