figure 10.1: Three parallelism patterns, one per panel: tensor parallel shards one layer’s weights 
(activations replicated; partial sums all-reduced every layer), pipeline parallel splits the layer stack 
into stages (hidden states move P2P; an idle bubble at fill/drain), and data parallel replicates the model 
while splitting the batch (training all-reduces gradients; inference replicas run unsynced). Each panel 
names what splits, what is replicated, and what communicates. Communication-specificity note: 
the TP collective is algorithm-dependent — a plain all-reduce of partial sums is one option, but fused 
kernels often use reduce-scatter + all-gather (or a single all-reduce) depending on the framework; 
the PP bubble size depends on microbatch scheduling (more microbatches shrink the bubble but add 
memory). The panels show the canonical configuration (TP all-reduce per layer; PP with a small 
fixed microbatch count); substitute the actual collective and schedule for the target stack. Grayscale 
note: each box’s text label carries its role, so the in-figure color key (blue = weights · orange = GPU · 
green = data · red = comms) is redundant, not load-bearing.
