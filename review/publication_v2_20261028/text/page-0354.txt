Reproducibility. The book’s quantitative examples are worked from the stated inputs in the sur­
rounding text; the home-lab measurements were made on the author’s own hardware under the 
configuration described in the chapter. Where a number is flagged as unresolved, the workspace did 
not have a first-party source at hand, and we say so rather than present an estimate as fact.
Home-lab scope. The author’s lab is a CPU-only workstation (Intel i5-3210M, four cores, 15 GB 
RAM). Measurements reflect that environment and the reduced-precision / small-model regime; they 
are used to illustrate mechanisms and orders of magnitude, not to characterize production hardware. 
Kernel-performance and throughput figures from public sources are to be treated as vendor-reported 
until re-measured on the target cluster. No H100/H200 production-performance claim in this 
book should be interpreted as a home-lab measurement unless explicitly labeled as such.
Code and data availability. The build scripts that produce this book (text → LaTeX → PDF, plus 
the figure generators) are in the accompanying repository. The figures are generated where possible 
(matplotlib and a hand-drawn diagram pipeline), so the arithmetic and layouts are inspectable rather 
than opaque artifacts.
Claim-to-source ledger. Every load-bearing number traces to a source by a fixed path, so a reader 
can re-derive it without guessing: (1) a [S#] key resolves to the matching entry in the References 
chapter, which gives the work, venue, and a stable identifier (arXiv id or first-party URL); all such 
sources were accessed as of the build date (v20260913). (2) a number derived from the canonical 
scenario traces to Ch 4, Table 4-2 (the single set of inputs every chapter cites). (3) the calculation 
itself is either the in-text arithmetic (stated with its operands) or the figure’s generator script in 
the repository (render/fig_*.py), which is reproducible from the stated inputs. A [1P] first-party 
claim is cited to its source but is a vendor statement, not an independent re-measurement; per the 
“moving target” note above, re-verify it against the current source before acting. This ledger is the 
mechanism; it does not substitute for the independent re-derivation and print proof that the release 
gates require.
Canonical parameter-and-unit ledger. Every derivative fleet/TCO/memory table cites this single 
ledger for its geometry, precision, and byte conventions, so a number is never silently re-based 
between the raw tensor overhead, the cache-block allocation, and the serving-engine observed 
footprint. The canonical scenario (Ch 4, Table 4-2) is full multi-head attention (MHA), 80 layers, 
hidden width 8192, BF16/FP16 KV, on an 8 × H100 host. The ledger is split into two blocks: the 
geometry and byte arithmetic and the planning and engine observations.
