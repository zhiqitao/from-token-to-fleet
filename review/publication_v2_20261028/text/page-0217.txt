16.5. Common Mistakes
• Comparing sticker price to per-token rate. A $/1K-token API quote already includes 
amortization; a card price tag does not. Amortize both.
• Ignoring the staff/ops term. Self-host “saves money” on paper and loses the moment two 
engineers are consumed full-time.
• Assuming 100% utilization. Idle cards are still burning electricity and depreciation; bake 
duty cycle in.
• Forgetting opportunity cost. A 6-month procurement cycle versus a same-week API inte­
gration is a real cost measured in time-to-value.
• Using peak capacity for cost-per-request. Peak sizing (40 rps) overstates cost if average 
(10 rps) utilization is what governs. (The headline $5.7/1K above does divide the peak-sized 
20-host fleet by average volume — deliberately: this workload must clear the 40 rps peak, so 
peak capacity is real cost here; the mistake applies when peak sizing is avoidable, e.g. batch or 
queueable traffic.)
16.6. Architecture Consequence
TCO is the final gate in the design loop (Ch12 candidates → Ch14 benchmark → Ch16 cost). It 
settles which candidate survives: the 70B 8×H100 self-host passes the capability screen and is 
analytically screened for feasibility — it would need a representative hardware benchmark 
to establish SLO-goodput (the C/W and roofline estimates of Chs. 7–8 are planning bounds, not 
a measured p95 TTFT/TPOT pass at the target offered load), and on TCO it beats the managed 
API at canonical volume but loses to scale-to-load cloud — so the surviving recommendation 
is conditional (self-host wins only if the staff/ops term is sunk and sustained near-peak utilization 
holds and a benchmark confirms the SLO; otherwise scale-to-load cloud at ~$2.8/1K is cheapest). This 
completes the chain from vague requirement to a defensible, costed architecture, while being honest 
that the TCO gate is not an unconditional win and that the SLO pass is provisional until benchmarked. 
It also feeds fleet decisions (Ch17-18): the break-even curve is what justifies buying a second host 
versus renting peaks, and the staff term is what pushes toward consolidation (Ch18).
