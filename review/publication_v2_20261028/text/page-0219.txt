16.8. End-of-Chapter Mini-Case: TCO Discipline and the Staff Term
A startup’s CTO shows the architect a warrant to buy two 8×H100 servers for the new internal RAG 
assistant, citing “we’ll save on token fees.” Applying TCO discipline, the architect does not dispute 
the raw token math. Instead they price it: at this startup’s actual early volume — ~2 rps average, 
~5M requests/month, and only 0.5 engineers fully available for GPU ops — the break-even against 
a managed API is this chapter’s own division: $40,000 ÷ $0.0208 ≈ 1.9M requests/month, so the 
current volume is already ~2.6× past the break-even. The honest number: self-hosting two servers 
~$40K/month all-in vs ~$104K/month API at current volume (5M × $0.0208) — a ~$64K/month 
saving in favor of self-hosting, with the staff term already inside the $40K (capex ~$11.6K + 
power ~$2.2K for two hosts leaves ≤ ~$26K for staff — upkeep is the power line already counted, so 
~$0.2K of the $26.2K remainder is unallocated — too small to dwarf a $64K saving). The staff term 
is on a different basis than Mode 1: the mini-case prices a startup’s 0.5-FTE operator (~$26K/mo — 
≈$624K/yr fully loaded for one engineer, a scenario value rather than a market rate), not Mode 1’s 
mature-operator alloc (~$10K/mo for 20 hosts) — re-price on one staffing basis before comparing. 
The token arithmetic therefore does not send this startup to the API; it points to self-hosting. Only 
one term can flip the decision: the opportunity cost of the GPU-ops time the two servers consume 
— the better part of the only engineer the startup can spare. To justify paying the API premium, 
that term must exceed ~$64K/month, about $770K/year of product work the startup is not doing. 
The architect’s verdict: start on the managed API now, and revisit self-host the moment the 
consumed engineer’s opportunity cost falls below ~$64K/month — for example when a 
second engineer frees up — then re-run the same model. Request volume is not the lever: more 
volume only widens the ~$64K gap. The CTO did not buy the servers. The break-even graph did 
not make the answer self-evident; it narrowed the whole decision to one labeled assumption — this 
startup values its half-engineer’s product time above $64K/month. A team that cannot say that, or 
that has a second engineer to spare, runs the same numbers and buys the servers.
