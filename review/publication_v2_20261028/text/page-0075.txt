The Anatomy of an AI Workload
• Token pricing: ~$1.20 per million input tokens, ~$2.00 per million output tokens on the same 
H100 instance (mid-tier managed-API list price, derived from cloud provider pricing as of 2026). 
The frontier-class API used in the Ch 16 TCO comparison is priced higher (~$2/$8 per 1M) — a 
different provider tier, not the same line item.
• Throughput per dollar: At 10 rps average, the system processes ~92,000 input tokens/s + 
~3,000 output tokens/s. The dollar denominator must be the whole fleet that serves this 
rate, not one host. At the ~5-host average the whole-fleet spend is ~$100/hour (≈ $0.0278 per 
second), so ~92,000 / 0.0278 ≈ ~3.3 million input tokens per cloud dollar and ~3,000 / 0.0278 
≈ ~108,000 output tokens per cloud dollar. These are modeled, whole-fleet figures (before 
SLO/headroom/failover). A separate quantity is a single host’s sustained-planning prefill rate 
(~19,800 tok/s at 35% MFU, Ch 8 — a planning rate, not a ceiling: the peak-derived ceiling is 
~56.5K tok/s): ~19,800 × 3,600 / $20 ≈ ~3.56M prefill tokens per host-dollar — a different 
denominator and a different rate, and not a claim that one host serves the offered load. Never 
present a tokens-per-dollar figure with the offered workload rate divided by a single-host price. 
(Chapter 5 expresses the same economics on a GPU list-price basis as tokens per dollar-hour; 
see its throughput-basis reconciliation note — the 9,000 is single-stream/the 3.3M is whole-fleet 
aggregate — before cross-chapter comparison.)
• Cost per request: At 10 rps, each request carries ~9,500 tokens (9,200 input + 300 output). At 
the per‑million rates, cost per request ≈ ($1.20 × 9.2 + $2.00 × 0.3) / 1,000 ≈ $0.01164 ≈ $0.012 per 
request per inference cycle. At 40 rps peak, cost scales linearly. Basis note — two different 
cost bases, not interchangeable. The $0.012 figure is derived from per-token market/API list 
prices ($1.20/M in, $2.00/M out) for the mid-tier managed API; it is a cloud-provider price a 
customer would pay per request on that hosted API. (The frontier-class API used in the Ch 16 
TCO comparison is priced higher — ~$2/$8 per 1M, ~$0.0208 per request; see the token-pricing 
bullet above for the tier distinction.) It is not the fleet owner’s marginal infrastructure cost. 
The owned-fleet cost is nearly all fixed capex/opex and barely scales per request, but it must 
be computed on the whole fleet, not one host: the $20/hr is the price of a single 8×H100 host, 
while the canonical 10 rps average / 40 rps peak needs ~5 hosts at average and ~20 at peak (Ch 
16/17). So the owned per-request cost is (N_hosts × $20/hr) ÷ (rps × 3600) ≈ (5 × $20) ÷ (10 
× 3600) ≈ ~$0.0028 per request at average, and the same ~$0.0028 at peak (20 × $20) ÷ (40 
× 3600) — the two coincide because host count and rps scale together. (Dividing one host’s 
$20/hr by the whole workload’s 10 rps would give ~$0.00056, but that is dimensionally wrong: 
one host cannot serve 10 rps of this workload.) Keep the two bases separate: use the per-token 
price for a hosted/API cost model, and the fleet $/hr ÷ fleet rps for an owned fleet. The two are 
juxtaposed in the cost-basis table below (§4.3) only to show the hosted-API pricing basis, not 
as an owned-fleet marginal cost.
