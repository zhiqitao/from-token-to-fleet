Candidate (c): KV-quantized smaller host.
We downgrade to a 7B-class model (7B × 2 bytes = 14 GB weights) with KV cache quantized to 4-bit. 
The per-token KV depends on the model’s own attention shape (layers × KV heads × head dim × 
bytes, Chapter 7), NOT the 70B’s constant: a typical 32-layer, 4096-hidden, full-MHA 7B carries ~0.52 
MB/token FP16, so ~0.13 MB/token at 4-bit → ~1.2 GB for the 9.2K context (vs the ~6 GB that comes 
from naively reusing the 70B’s 2.62 MB/token ÷ 4). Total residency: 14 GB + ~1.2 GB ≈ ~15 GB, which 
fits on a single H100 (80 GB) with large headroom. The trade-off is a quality question, and here we 
must be careful not to assert an architectural theorem where one does not exist. Whether a 7B-class 
model can match the 70B model’s answer quality on this workload is not derivable from parameter 
count — a newer or task-specialized 7B can beat an older or general 70B on some tasks. It is an 
empirical question answered only by running the actual evaluation set. The correct architectural 
lesson is the quality gate: the smaller candidate must pass the capability/quality gate on the true 
evaluation set; if it fails there, no amount of infrastructure optimization fixes that failure. So candidate 
(c) is flagged for measurement against the quality gate, not dismissed by parameter counting. The 
4-bit KV cache is a memory optimization, not a quality one; aggressive KV quantization can add its 
own quality penalty that must also be validated on the target workload. Throughput is genuinely 
much higher on the smaller model — a 7B prefill costs only ~14 GFLOP/token, so a single card sustains 
tens of thousands of prefill tokens/s (vs ~2,471 per GPU for the 70B, Chapter 8) — but that throughput 
advantage is only useful if the quality gate is first satisfied. The candidate is therefore provisional: its 
fate depends on the measured quality gate, which Chapter 14 (the capability screen) administers. 
This candidate illustrates the extreme end of the KV-quantization space: the memory footprint is 
trivially small, but neither quality nor throughput makes it competitive for this workload.
Memory/residency arithmetic summary. The canonical weights (140 GB) + KV (24 GB FP16 at
