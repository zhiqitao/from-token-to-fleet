[!TIP]\r\n> This release brings FLUX.3 Image Klein, Bria Fibo 2.0, Kandinsky 6, SANA-WM, and RFD4-Proteína to Diffusers, alongside new adapter support, hardware integrations, and modular pipelines.\r\n> 🚨 Python 3.11 or newer is now required.\r\n\r\n## FLUX.3 Image Klein\r\n\r\nFLUX.3 Image Klein from Black Forest Labs supports text-to-image generation and editing with one or more reference images. Both the base and step-distilled checkpoints are available through `ModularPipeline`, with an integrated prompt upsampler that turns short requests into detailed captions and supports layout instructions with bounding boxes. The integration also includes single-file transformer loading and BFL FP8r and NVFP4 checkpoints.\r\n\r\nLoad the pipeline with `ModularPipeline.from_pretrained(...)`, then load its weights with `load_components(...)`. See the [FLUX.3 documentation](https://huggingface.co/docs/diffusers/main/en/api/pipelines/flux3) for examples and guidance on prompt upsampling, editing, and memory use.\r\n\r\n## Bria Fibo 2.0\r\n\r\nBria Fibo 2.0 supports image generation from structured JSON captions and editing with up to five reference images through `BriaFibo2Pipeline`. The integration includes the dev checkpoint and the edit-turbo checkpoint, which runs in four steps without classifier-free guidance. See the [Fibo 2.0 documentation](https://huggingface.co/docs/diffusers/main/en/api/pipelines/bria_fibo2) for the supported prompt formats.\r\n\r\nLoRA loading and DreamBooth LoRA training examples are included for text-to-image and image editing. Thanks to [@muhammadali-afridi](https://github.com/muhammadali-afridi) for the model integration (#14991).\r\n\r\n## Kandinsky 6\r\n\r\nKandinsky 6 generates video with synchronized audio from text or a reference image through `Kandinsky6TI2VAPipeline`. A separate `Kandinsky6SRPipeline` provides video super-resolution. The integration supports Pro and Lite generation checkpoints, including distilled variants, and introduces `PiflowScheduler` for the distilled models. See the [Kandinsky 6 documentation](https://huggingface.co/docs/diffusers/main/en/api/pipelines/kandinsky6) for checkpoint-specific settings and super-resolution requirements. Thanks to @lefff for the model integration (#14949).\r\n\r\n## SANA-WM\r\n\r\nSANA-WM generates video from a starting image, a text prompt, and a camera trajectory. Control the camera with explicit poses or a WASD/IJKL action string, then optionally refine the output with the separate LTX-2 refiner. See the [SANA-WM documentation](https://huggingface.co/docs/diffusers/main/en/api/pipelines/sana_wm) for the two-stage workflow.\r\n\r\nThanks to [@lawrence-cj](https://github.com/lawrence-cj) for the integration (#13881).\r\n\r\n## RFD4-Proteína\r\n\r\nRFD4-Proteína from the Baker Lab and NVIDIA brings biomolecular design to Diffusers. It jointly generates protein sequences and all-atom structures while conditioning on molecular context such as binding targets, motifs, or ligands. The integration includes the pipeline, transformer, autoencoder, schedulers, and LoRA loading. Preparing model inputs and writing CIF files uses the separate `rfd4-proteina-prep` package; see the [RFD4-Proteína documentation](https://huggingface.co/docs/diffusers/main/en/api/pipelines/rfd4_proteina).\r\n\r\nThanks to [@kierandidi](https://github.com/kierandidi) for the integration (#15088).\r\n\r\n### Other highlights\r\n\r\n- **Qwen-Image 2.1:** new modular pipelines and tensor parallelism support. ([#14976](https://github.com/huggingface/diffusers/pull/14976), [#14865](https://github.com/huggingface/diffusers/pull/14865))\r\n- **More hardware support:** TorchTPU integration covers eager execution, `torch.compile`, and tensor parallelism. Tensor parallelism also gains Intel XPU support. ([#14039](https://github.com/huggingface/diffusers/pull/14039), [#15013](https://github.com/huggingface/diffusers/pull/15013))\r\n- **LoKr adapters:** load LyCORIS Kronecker-product adapters for Z-Image and FLUX.2, including Klein. ([#14163](https://github.com/huggingface/diffusers/pull/14163))\r\n- **LTX-2 motion control:** `motion_speed` controls the positional time base independently of playback frame rate. Use a compatible adapter for speeds far from the default, such as the LTX-2.5 slow-motion control LoRA. ([#14967](https://github.com/huggingface/diffusers/pull/14967))\r\n- **KVAE-Audio:** `AutoencoderKLKVAEAudio` adds encoding and decoding for 48 kHz audio. ([#14384](https://github.com/huggingface/diffusers/pull/14384))\r\n- **Caching:** MagCache now supports FLUX.2. ([#14756](https://github.com/huggingface/diffusers/pull/14756))\r\n- **Adapter fixes:** Z-Image honors the LoRA scale in `joint_attention_kwargs`, Qwen-Image applies `.alpha` scaling to `lora_A`/`lora_B` checkpoints, and text encoders correctly report active adapters. ([#15015](https://github.com/huggingface/diffusers/pull/15015), [#15016](https://github.com/huggingface/diffusers/pull/15016), [#14961](https://github.com/huggingface/diffusers/pull/14961))\r\n- **Pipeline fixes:** preserve explicit timesteps in `FlowMatchEulerDiscreteScheduler`, fix Anima text encoder exports and standalone core denoising, and preserve the three-value return from `InpaintProcessor.preprocess` when no mask is supplied. ([#14956](https://github.com/huggingface/diffusers/pull/14956), [#14943](https://github.com/huggingface/diffusers/pull/14943), [#14481](https://github.com/huggingface/diffusers/pull/14481))\r\n\r\n### Deprecations and compatibility\r\n\r\n- **Python 3.10 support is dropped.** Upgrade to Python 3.11 or newer before installing this release. Custom workflows should pass unpacked latents to their decode blocks. The fallback for packed latents is deprecated for removal in 0.47.0. ([#14737](https://github.com/huggingface/diffusers/pull/14737))\r\n- **Hub compatibility:** the supported `huggingface_hub` range is now `>=1.32.0,<3.0`. ([#14863](https://github.com/huggingface/diffusers/pull/14863))\r\n- **TorchAO imports:** having a TorchAO version older than 0.15 installed no longer breaks model imports. [!TIP]\r\n> This release features several new pipelines, including LTX2.5, MiniMax H3, and Wan Animate 2. We're also graduating Modular Diffusers out of the experimental phase and announcing its stable support. Additionally, this release includes minimal support for tensor-parallel. There's a lot more that went down in this release. So, please consult the notes for details. \r\n\r\n## New Pipelines\r\n\r\n### MiniMax-H3\r\n\r\n[**MiniMax-H3**](https://huggingface.co/docs/diffusers/main/api/pipelines/minimax_h3) generates video and its soundtrack together. A single transformer denoises one packed sequence containing the text conditioning, the conditioning media, and the target video *and* audio latents — there is no separate vocoder and no post-hoc audio pass. Its conditioner is a `Qwen3VLForConditionalGeneration` whose unnormalized 50th-decoder-layer hidden state is read instead of the last one.\r\n\r\nMiniMax-H3 is integrated as [Modular Diffusers](https://huggingface.co/docs/diffusers/main/modular_diffusers/overview) blocks only — `MiniMaxH3Blocks` and their `MiniMaxH3ModularPipeline` are the whole integration. The conversion ships both checkpoint partitions in one repository and exposes three workflows (`t2va`, `fl2va`, `ref2va`) that can be pruned at `from_pretrained` time so only that task's components are declared and downloaded.\r\n\r\n### MiniMax Music 3\r\n\r\n[**MiniMax Music 3**](https://huggingface.co/docs/diffusers/main/api/pipelines/minimax_music3) produces complete songs up to five minutes long from lyrics and a music description, with expressive vocals and long-range structure. It is a hybrid of an autoregressive and a diffusion stage: an 8B Qwen3-based global language model predicts one semantic audio token per frame while a small depth decoder fills in seven residual RVQ codebooks, and their fused hidden states condition a 2.4B flow-matching transformer that produces Flow-VAE latents in overlapping chunks. A DAC-style decoder turns the latents into 44.1 kHz stereo audio.\r\n\r\n### Stable Audio 3\r\n\r\n[**Stable Audio 3**](https://huggingface.co/docs/diffusers/main/api/pipelines/stable_audio_3) is a text-to-audio model from Stability AI that generates high-quality stereo audio at 44.1 kHz. It uses a rectified-flow DiT conditioned on a frozen T5Gemma text encoder (via cross-attention) and on duration (a float embedded by `StableAudio3DurationEmbedder` and used for adaptive layer norm), and decodes with the SAME (Semantically-Aligned Music Encoder) autoencoder, `AutoencoderSAME`.\r\n\r\nThree pipelines ship: `StableAudio3Pipeline`, `StableAudio3AudioToAudioPipeline`, and `StableAudio3InpaintPipeline`.\r\n\r\nThanks to @buffett0323 for the contribution (https://github.com/huggingface/diffusers/pull/14119).\r\n\r\n### LTX-2.5\r\n\r\n[**LTX-2.5**](https://huggingface.co/docs/diffusers/main/api/pipelines/ltx2#ltx-25) reuses the existing `LTX2Pipeline` / `LTX2VideoTransformer3DModel` / `AutoencoderKLLTX2Video` classes — there is no separate pipeline class. The user-visible difference is the text encoder: LTX-2.5 is paired with a Gemma 4 (`gemma4_unified`) checkpoint, loaded automatically from a converted LTX-2.5 repo.\r\n\r\n[`Lightricks/LTX-2.5-Diffusers`](https://huggingface.co/Lightricks/LTX-2.5-Diffusers) ships both the distilled DiT (`transformer/`) and the full/SFT DiT (`transformer_full/`), plus everything two-stage generation needs. Alongside the checkpoint support, this release adds:\r\n\r\n- `LTX2VideoDiffusionDecoderModel` and `LTX2VideoDiffusionDecodePipeline` — a second video decoder over the same latent space, so latents are interchangeable between decoders.\r\n- A `duration_head` that predicts shot length from the text-connector output, so `num_frames` is auto-predicted by default when the loaded pipeline has one.\r\n- Prompt enhancement through a separate off-the-shelf `google/gemma-4-E2B-it` checkpoint (`enable_prompt_enhancement=True`).\r\n- `LTX25AutoBlocks` for Modular Diffusers ([#14453](https://github.com/huggingface/diffusers/pull/14453)).\r\n\r\n### Wan-Animate-2\r\n\r\n[**Wan-Animate-2**](https://huggingface.co/docs/diffusers/main/api/pipelines/wan_animate_2) by the Alibaba Wan Team animates a reference character image with the motion of a driving video. The driving video is processed in fixed-length segments: each segment runs a reference-extraction pass that caches the driving segment's K/V in every transformer layer, denoises against that cache, and is decoded inside the loop, because the next segment conditions on the previous segment's decoded tail frames.\r\n\r\nTwo presets are available — the base checkpoint samples with classifier-free guidance, and the distilled checkpoint samples in few steps without it. Guidance is owned by the pipeline's guider component, so there is no `guidance_scale` argument.\r\n\r\nThanks to @kelseyee for authoring the integration (https://github.com/huggingface/diffusers/pull/14413).\r\n\r\n### JoyAI-Image-Edit-Plus\r\n\r\n[**JoyAI-Image-Edit-Plus**](https://huggingface.co/docs/diffusers/main/api/pipelines/joyimage_edit_plus) extends the JoyAI-Image family (an 8B MLLM paired with a 16B MMDiT) to multi-image instruction-guided editing. All `Flax*` classes and the `flax` extras are gone.\r\n- **Mixed-rank LoRAs without alpha keys now load at their intended scale** ([#14409](https://github.com/huggingface/diffusers/pull/14409)). Previously `get_peft_kwargs` took `lora_alpha` from the first entry of the rank dict and never revisited it, so every module whose rank differed from the first key's rank got an arbitrary, key-order-dependent scale. Ranks are now mirrored into the alphas when a checkpoint brings no alpha information (the diffusers/PEFT convention: alpha == rank, scale 1.0). Adapters with a declared alpha keep it, and uniform-rank adapters are unaffected. Existing mixed-rank, no-alpha LoRAs will now produce different (correct) results.\r\n- **`torch_dtype` is deprecated in favour of `dtype`** ([#14205](https://github.com/huggingface/diffusers/pull/14205), [#14313](https://github.com/huggingface/diffusers/pull/14313)), following `transformers`. `torch_dtype` still works but warns, and will be removed in 1.0.0. A Qwen3-VL text encoder provides the conditioning — hidden states from twelve decoder layers are tapped per token and fused inside the transformer by a small text-fusion stage — and images are decoded with the Qwen-Image VAE. Both the base (midtrain) and TDM (distilled, few-step) checkpoints are supported, alongside a LoRA DreamBooth trainer.\r\n\r\n- PR: [https://github.com/huggingface/diffusers/pull/14045](https://github.com/huggingface/diffusers/pull/14045)\r\n- Docs: [https://huggingface.co/docs/diffusers/main/api/pipelines/krea2](https://huggingface.co/docs/diffusers/main/api/pipelines/krea2)\r\n\r\nThanks to @EleaZhong and @Abhinay1997 for the contribution.\r\n\r\n### DreamLite\r\n\r\n[**DreamLite**](https://huggingface.co/docs/diffusers/main/api/pipelines/dreamlite) is a text-to-image and image-editing model from ByteDance. It pairs a custom 2D U-Net (`DreamLiteUNetModel`) with the `Qwen3-VL` multimodal encoder as its prompt / image-instruction encoder, and uses an `AutoencoderTiny` (TAESD-style) VAE for fast latent encode/decode. A distilled `DreamLiteMobilePipeline` targets on-device, low-latency generation.\r\n\r\n- PR: [https://github.com/huggingface/diffusers/pull/13815](https://github.com/huggingface/diffusers/pull/13815)\r\n- Docs: [https://huggingface.co/docs/diffusers/main/api/pipelines/dreamlite](https://huggingface.co/docs/diffusers/main/api/pipelines/dreamlite)\r\n\r\nThanks to @Carlofkl for the contribution.\r\n\r\n### PRX Pixel\r\n\r\n[**PRXPixel**](https://huggingface.co/docs/diffusers/main/api/pipelines/prx_pixel) is a pixel-space text-to-image generation model by Photoroom.
